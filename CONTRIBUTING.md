# Contributing to Osmdle

Thank you for taking the time to help Osmdle. Bug reports, data corrections,
and ideas are all welcome (ﾉ◕ヮ◕)ﾉ

Osmdle is maintained by one person in their spare time, so replies may take a
few days.

## Before you start

- Search the open issues and pull requests before filing something new.
- Open an issue before writing code for anything larger than a small fix. It is
  easier to agree on an approach than to turn down finished work.
- Report security problems privately, as described in
  [SECURITY.md](./SECURITY.md), never in a public issue.
- Every thread is covered by the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Setup

Node.js 24 (see `.nvmrc`) and npm 11 are required.

```bash
npm ci
npx lefthook install
npm run dev
```

The second command is needed because `.npmrc` sets `ignore-scripts=true`, which
skips the `prepare` step that would install the hooks. The dev server runs on
http://localhost:3000.

## Checks

Run the same checks as CI before opening a pull request:

| Command                 | What it covers                  |
| ----------------------- | ------------------------------- |
| `npm run lint`          | Biome formatting and linting    |
| `npm run typecheck`     | Next.js types and `tsc`         |
| `npm test`              | Game logic tests                |
| `npm run data:validate` | Catalog and snapshot invariants |
| `npm run build`         | Production build                |

CI also runs `npm audit` and `npm audit signatures`, so a local run can still
fail when a dependency advisory lands.

The pre-commit hook formats staged files and type-checks them; the commit-msg
hook runs commitlint.

## Style

- Biome is the only formatter and linter. Just run `npm run format`, and do not
  add ESLint or Prettier, which would fight `biome.json`.
- TypeScript is strict, and imports from the repository root use the `@/*`
  alias.

## Commits

This project uses [Conventional Commits](https://www.conventionalcommits.org):
lowercase, imperative mood, and a subject of 50 characters or fewer.

```text
fix(game): add breathing room to mobile cards
ci: attribute sync commits to the app bot
docs: add contributor covenant code of conduct
```

Leave a blank line between the subject and the body. Without it, git treats the
whole paragraph as the subject, and GitHub shows it as one long title.

## Data

Two files matter here, and only one of them is edited by hand:

- `data/catalog.json` is the curated list of elements.
- `data/elements.json` is generated by `npm run data:sync`. Never edit it by
  hand, since the next sync overwrites it.

The catalog must contain exactly 300 elements, split across fixed family quotas
(civic 30, health 10, emergency 10, food 20, shop 20, transport 40, highway 25,
water 30, nature 25, landuse 25, sports 25, tourism 20, buildings 10, street
10). Adding an element therefore means removing another one from the same
family.

`nature` holds wild features only; land that people use belongs in `landuse`.

Each element gets its description and image from the OpenStreetMap Wiki page for
its tags. Descriptions are not overridden per element, and a missing one falls
back to the element title.

### Changing an element

If you are considering adding, removing, or replacing an element, open an issue
to discuss it first. 

Every element fills a slot in a fixed family quota, so the change has to make
room inside its own family.

Then edit `data/catalog.json` and run:

```bash
npm run data:sync
npm run data:validate
```

The sync talks to [Taginfo](https://taginfo.openstreetmap.org) and follows its
[API policy](https://wiki.openstreetmap.org/wiki/Taginfo/API): responses are
cached in `.cache/` and requests are paced. Deleting the cache is safe and only
costs a refetch.

The monthly data refresh arrives as its own bot-authored pull request. Keep
that separate from code changes.

## Pull requests

- Keep each pull request to one concern, and link the issue it resolves.
- Explain what changed and why; the diff already shows the how.
- Include a screenshot or recording for anything that changes the interface.
  It helps us check and revise the code faster.
